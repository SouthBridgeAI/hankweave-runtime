## [0.10.0] - 2026-08-18

### Added
- **Startup catalog preflight for Pi-run models** — the startup self-test now verifies every Pi-routed model against Pi's own model catalog (a new `model_catalog` check), using the exact resolution rule codon launch applies (including `-high`/`-xhigh` effort-suffix fallback and models added via `~/.pi/agent/models.json`). A model the registry knows but Pi cannot serve (e.g. `glm-5.1`), a typo'd `pi/<provider>/<model>` spelling, or an OpenRouter id outside Pi's vendored list now fails at config load with the available catalog ids as suggestions, instead of failing mid-run at codon launch after earlier codons have already spent money.

### Changed
- **BREAKING: strict hank ref paths** — every path a hank author writes into a hank's config documents (`globalSystemPromptFile`, `promptFile`, `appendSystemPromptFile`, `rigSetup[].copy.from`, and string-valued `sentinels[].sentinelConfig` in `hank.json`; `systemPromptFile`, `userPromptFile`, and `structuredOutput.schemaFile` in sentinel config files) is now validated against three rules: it must be a portable relative POSIX path (no leading `/`, no backslash anywhere, no drive-letter prefix, no NUL bytes — the same string means the same file on every platform), it must stay inside the hank directory at every step of the spelling (`../prompts/x.md` from a subdirectory is fine; a ref that ever climbs above the hank root is rejected, even if it points back inside), and it must not pass through a symlink inside the hank (broken symlinks included; symlinks *above* the hank directory — e.g. macOS `/tmp` — are fine, the hank dir is realpath'd first). `rigSetup[].copy.from` trees additionally reject symlinks and special files (FIFOs, devices) anywhere inside them, including a special file named directly as the source. The rules are enforced identically at schema validation and at runtime load — backed internally by a new shared ref resolver (`server/hank-refs.ts`) and a branded `ValidatedRef` type, so no code path can read an authored ref without passing the gate. Hanks that referenced files via absolute paths or `../` escapes now fail at validation/load with the specific rule named; move those files inside the hank directory. Spec: `intermediates/63-strict-hank-paths/`
- **Late-bound harness selection** — `ModelInfo` now always carries the model's real identity (`providerId` = registry provider, `modelId` = canonical id); the retired `"pi"` pseudo-provider encoding is gone. Which harness runs a codon (Claude Agent SDK vs. embedded Pi) is computed at dispatch time by `selectHarness()`, and explicit `pi/<provider>/<model>` spellings set a new optional `harnessOverride: "pi"` field instead of rewriting the model's identity. Consequences:
  - Persisted execution plans no longer encode a routing decision. Plans saved with the old `providerId: "pi"` encoding are migrated on resume (split on the first slash back to the real provider). Because old plans don't record whether `pi` was user-forced, all legacy `pi` entries are treated as routing-derived — a legacy plan that explicitly forced an Anthropic model onto Pi will re-route to the Claude Agent SDK on resume.
  - Pi provider aliasing (`zhipuai`→`zai`) and OpenRouter re-routing (`moonshotai` → `openrouter/moonshotai/…`) are now applied at dispatch instead of frozen into the plan at validation, so resumed runs pick up current routing rules after an upgrade (routing bug-fixes apply retroactively mid-hank). This also means an explicit `pi/moonshotai/…` spelling now routes through OpenRouter like registry-resolved moonshotai models always did.
  - Cost tracking prices every model by the same `<provider>/<model>` key. Models that were previously priced by a pi-routing string that missed the registry (e.g. `zai/glm-*`, `openrouter/moonshotai/kimi-*`) now hit their real registry pricing entry, so incremental cost estimates appear for them.
  - Display names for Pi-run models show the real model name instead of `pi: <provider>/<model>`.
- Updated the pi packages (`@earendil-works/pi-coding-agent`, `@earendil-works/pi-ai`) to 0.84.2 — adds `gemini-3.7-flash` to pi's model catalog, which was already in the registry but failed the new pi-catalog preflight on 0.84.1
- Updated model data — refreshed `models-dev-data.json` from models.dev (185 → 188 providers, 6,120 → 6,472 models; new providers `scnet-token-plan`, `amd`, `runinfra`). No new OpenAI/Anthropic/Google models

### Fixed
- **Sentinel file refs resolved against the wrong config directory** — the runtime flattened the loader's per-config directories down to the first one, so every sentinel in a codon resolved `systemPromptFile`, `userPromptFile`, and `structuredOutput.schemaFile` against the *first* config's directory — silently reading the wrong file, or failing with ENOENT for configs at other depths. Each sentinel now resolves its refs against its own config file's directory
- **A FIFO (or other non-regular file) at a user-authored path no longer hangs the CLI** — `readFileSync` on a named pipe blocks forever, synchronously, so a FIFO at `promptFile`, `globalSystemPromptFile`, a sentinel config or its nested refs, the hank file itself (hashed before validation), or even `hankweave.json` (read for telemetry — this one froze `--help`) wedged the process with no error. Every runtime read of a user-authored path now checks the target is a regular file first (shared `checkRegularFile` in `server/fs-guards.ts`) and fails with "is not a regular file"; directories get the same clear message instead of a raw EISDIR
- **Rig `copy.from` can no longer name the hank directory itself** — copying the whole hank dir swept `hank.json`, prompts, and any pack/runtime artifacts into the rig (and cannot be represented faithfully in a packed bundle). Validation now rejects it — lexical spellings (`.`, `sub/..`) and symlinks back to it included — and suggests moving the files into a subdirectory and copying that
- **Published `hank.schema.json` was missing root fields** — the authoring schema it is generated from lacked `requirements`, `globalSystemPromptFile`, and `globalSystemPromptText`, and since the authoring root is `.strict()`, editors validating against the published schema flagged those legitimate fields as unknown keys. The root fields are now shared between the authoring and runtime schemas (with a parity test so they can't drift again), and CI regenerates the committed schemas on every PR and fails on any difference — previously only the release script regenerated them, and its preflight merely warned
