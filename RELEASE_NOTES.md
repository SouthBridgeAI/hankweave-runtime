### Fixed
- **Published package crashed at startup with `SyntaxError: ... does not provide an export named 'getModelCapabilities'`** — 0.13.0's bundle contained `@ai-sdk/amazon-bedrock` 3.0.141 instead of the locked 3.0.114, because the Deno cross-runtime tests re-resolved `node_modules` (ignoring `bun.lock`) before the publish build. Workaround for 0.13.0: override `@ai-sdk/anthropic` to `2.0.110`.

## [0.13.0] - 2026-10-22

### Added
- **Runtime model catalog: new models run without a hankweave release** — a model is accepted once the harness that runs it confirms it (see the BREAKING entry under Changed), and priced and described from a catalog: the bundled models.dev snapshot, a cached copy of the live models.dev catalog (refreshed in the background), LiteLLM prices, a reviewed overlay of corrections that ships with each release, the user's own `models` blocks, and, for a model none of those lists, the harness's own row (Pi's catalog). Hosts contacted: `models.dev` and `raw.githubusercontent.com` (LiteLLM's price list) in the background when their cached copies are more than six hours old, `pi.dev` for pi's catalog (on a miss, bounded, and in the background), and, only for an Anthropic id the catalog lacks, Anthropic's `GET /v1/models/<id>` with your key (cached 30 days); `noOnlineModelChecks` turns all of it off. Cache lives in `~/.hankweave/model-catalog/` (`HANKWEAVE_MODEL_CATALOG_DIR` to move it). See `intermediates/70-model-catalog/spec.md` and `intermediates/72-harness-first-models/plan.md`.
- **`models` blocks in `hank.json` and `hankweave.json`** — declare a model no catalog source knows yet, or correct a known model's price and limits: `{ "id": "anthropic/claude-sonnet-6", "basedOn": "anthropic/claude-sonnet-5-5", "cost": { "input": 3, "output": 15 } }`. A declared `cost` is what budgets use and what the run records, even for a model the harness prices itself; a cache rate it omits keeps the `basedOn` (or catalog) record's. An entry for a model already in the catalog may give just its `cost`, and keeps the record's confidence. An entry must name a provider the catalog lists (declare models reached through `openai-codex` as `openai/…`). A declared model Pi's catalog lacks is added to Pi's catalog for the run from its newest sibling. `hankweave.json` entries win over the hank's. Replaces the compiled-in `models-custom-data.json`.
- **Model provenance** — `--validate` and the startup summary print a Models table (spelling → model, harness, confidence, price, source, and what confirmed the harness can run it: `catalog`, `pi catalog`, `pi.dev`, `anthropic GET /v1/models`, `adopted from <sibling>`), and the journal records an `info` event when a codon's model is provisional or user-defined, or its price is unknown, disputed (LiteLLM lists it more than 5% higher; budgets use the higher rate), or declared (a `models` block or overlay correction). Provenance is persisted with the model in the execution plan, so a resumed run prices exactly as it was validated.
- **Model overlay** (`server/llm/internal/model-overlay.json`) — reviewed price and limit corrections, each citing a source. No name data: no aliases, no retirements. It ships inside each release; nothing downloads a newer copy. Seeded with DeepSeek's published peak rates for Flash and V4 Pro.
- **`scripts/verify-models.ts`** — probes models with real keys (reply, priced usage, tool call, forced tool choice, image input; `--codon` adds one real hankweave codon, `--context-probe` a near-limit prompt) and proposes limit corrections for the overlay. Replaces `scripts/e2e/test-new-models.ts`.
- **`budget.unpricedModels` in `hankweave.json`** — `"estimate"` (default) counts an unpriced model's tokens at a flagged ceiling (the highest price among its siblings, those released in the last year first); `"refuse"` fails validation instead.
- **`noOnlineModelChecks` in `hankweave.json`** (or `HANKWEAVE_RUNTIME_NO_ONLINE_MODEL_CHECKS=1`) — stops Hankweave looking models up online (models.dev, LiteLLM prices, pi.dev, providers' model lists); the model catalog then uses the bundled data plus its cache. Calls to the models themselves are unaffected. The test runner sets it for every suite.
- **`bun scripts/release.ts <bump> --refresh-models`** — refreshes the bundled snapshot (the offline floor) as its own commit at release time.

### Changed
- **BREAKING: every model is a fully qualified `<provider>/<model>` id, confirmed by its harness before anything else** — written exactly as the harness that runs it knows it, case-sensitive; trim is the only normalisation. Gone: shortcuts (`sonnet`, `opus`, `haiku`, `fable`, `gemini-flash`, `gemini-pro`, `gpt-5.6`), bare ids (`claude-sonnet-5-5`, `gpt-5.2`), provider aliases (`zhipuai/…` and `z-ai/…` for `zai/…`, `moonshot/…`), `opencode/` and `moonshotai/` rerouting, overlay aliases and retirements, and `pi/…` passthroughs no catalog confirms. Every place a model is written is checked — `hank[].model` (loops included), `overrides.model`, `hankweave.json` `model`, `--model`, `HANKWEAVE_RUNTIME_MODEL`, and sentinel models — and a rejected name says what was written, the rule, and ids to copy (`'sonnet' is not a model id; model shortcuts were removed. The newest Anthropic Sonnet is anthropic/claude-sonnet-5-5.`). Validation order: the name (offline); then the harness that would run it — the Claude Agent SDK for `anthropic` and Anthropic-family `amazon-bedrock` ids, Pi for every provider Pi has (its built-ins plus your `~/.pi/agent/models.json`), the AI SDK for sentinels — confirms it can, credentials included (Pi asks its own auth resolution for every provider, so a ChatGPT login or a key only in a codon's `env` block counts); only then is the model priced from the catalog. A provider no harness runs (the ~200 resellers models.dev lists that no harness has a client for) is rejected by name with providers listing the same id. Shadowed overrides (e.g. a `hankweave.json` model under `--model`) are checked by name only. Replay, `--cleanup`, `hankweave pack` and bundle verification check names and catalog membership only — no credentials, no network. Migration: `sonnet` → `anthropic/claude-sonnet-5-5`, `haiku` → `anthropic/claude-haiku-4-5`, `gpt-5.6` → `openai/gpt-5.6-sol` (or `openai-codex/gpt-5.6-sol` on a ChatGPT login), `zhipuai/glm-5.2` → `zai/glm-5.2`, `kimi-k3` → `moonshotai/kimi-k3` (now runs on Pi's own `moonshotai` client: set `MOONSHOT_API_KEY`) or `openrouter/moonshotai/kimi-k3`. `opencode/<id>` now means OpenCode Zen's model (Pi's `opencode` provider, `OPENCODE_API_KEY`), no longer a rewrite to `pi/…`. Sentinels whose provider has no credentials are still skipped, not fatal.
- **Pi reads a hankweave-owned model store** — pi's pi.dev catalog overlay is refreshed in the background into `~/.hankweave/model-catalog/pi-models-store.json`, so a standalone `pi` run no longer changes which models hankweave accepts. Each run reads its own copy of that store, taken at startup, so the prices and limits pi reports cannot change between codons; the background refresh updates the shared store for the next run, and a shared store left truncated by a killed process is reset instead of blocking every later refresh. A model pi's catalog lacks but hankweave's knows is added for the run from its newest same-family sibling in pi's catalog; the user's `~/.pi/agent/models.json` is merged in, never modified.
- **Provider health checks list models instead of generating text** — sentinel health checks for Anthropic, OpenAI, Google, DeepSeek, and Groq call the model-list API (free, no pinned model id); Bedrock keeps its one-token generation check.
- **Dollar budgets see unpriced and zero-priced models** — the preflight warning now covers run-wide budgets from `hankweave.json` and `--max-cost`, reports the ceiling estimate for an unpriced model, and warns when a model's price is $0, whether models.dev lists it that way or LiteLLM supplies it.
- Updated `@anthropic-ai/claude-agent-sdk` 0.3.267 → 0.3.284 (extraction cache key bumped to match), the pi packages (`@earendil-works/pi-coding-agent`, `@earendil-works/pi-ai`) 0.85.1 → 0.87.1 (pi shim bundle rebuilt against 0.87.1; 0.87.1 adds GPT-6 Luna and GPT-6 Sol to the pi model catalog), and the codex shim's `@openai/codex-sdk` 0.153.4 → 0.159.0 (shim rebuilt; `CODEX_SDK_VERSION` cache key stamped 0.159.0). pi-ai 0.87.1 makes provider-level `stream()` take a normalized transcript context, so `scripts/verify-codex-auth.ts` now wraps its request in `normalizeContext()`. pi-ai 0.87.1 also drops the DeepSeek catalog entry `deepseek-v4-flash` in favour of `deepseek-flash` (DeepSeek V4.1 Flash); DeepSeek has retired the V4 Flash model and serves the legacy name as V4.1 Flash at Flash pricing, so hanks should use `deepseek/deepseek-flash`; `deepseek/deepseek-v4-flash` still runs (models.dev lists it, so hankweave adds it to pi's catalog from `deepseek-flash`), priced at models.dev's V4 Flash rate. The keyless test fixtures, the pi/registry unit tests, the `/bench` model table, and the DeepSeek LLM-proxy health-check model all moved to `deepseek-flash`
- Updated model data — refreshed `models-dev-data.json` from models.dev (213 → 232 providers, 7,436 → 8,902 models). New first-party models include `anthropic/claude-opus-5-5` (Claude Opus 5.5), `anthropic/claude-sonnet-5-5` (Claude Sonnet 5.5), `anthropic/claude-haiku-5-5` (Claude Haiku 5.5; note Anthropic prices prompts over 100k tokens at five times the listed rate, which no catalog source carries), `openai/gpt-6-luna` (GPT-6 Luna), `openai/gpt-6-sol` (GPT-6 Sol), `openai/gpt-6.1-sol`, `openai/gpt-daybreak-blue-latest` (Daybreak Blue), `openai/gpt-daybreak-red-latest` (Daybreak Red), `google/gemini-4-argon` and several Mistral ids. The Daybreak ids are not in the pi 0.87.1 model catalog yet; hankweave adds them to pi's catalog for the run (from pi.dev's catalog, or offline as a row copied from `gpt-6-luna`; see "Pi reads a hankweave-owned model store"), so Pi confirms them at startup. models.dev also repriced the regional Bedrock Anthropic entries (`us.`/`eu.`/`au.`/`jp.` Sonnet 4.6 and Haiku 4.5 now carry the 10% regional premium, e.g. `us.anthropic.claude-haiku-4-5-20251001-v1:0` 1/5 → 1.1/5.5 per MTok), which the cost tracker picks up from the registry, and now carries `family` fields for the DeepSeek rows. A new unit test (`tests/unit/published-prices.test.ts`) checks the snapshot's rates for the models hanks and tests run against the rates copied from each provider's own pricing page
- Stopped rebuilding `shims/` in model bumps (nothing loads them; kept as reference per #171), removed the unused `models-custom-data.json` and `models-dev-data.backup.json`, and the unreachable `MODEL_SHORTNAMES` table in the pi manager.
- Removed the runtime PID file; ownership uses only the in-directory `proper-lockfile` lease. Attach port discovery uses `execution-meta.json` under `runtime.port`; use `--port` to attach to older runtimes. Run recovery uses persisted execution state.
- **Runtime ownership is acquired once at each command boundary.** The command acquires a `RuntimeLock` before setup and releases it after finalization. Runtime startup, journal maintenance, auto-restore, and cleanup share this API; run recovery and attachment metadata are separate.
- **Runtime exclusion uses a `proper-lockfile` lease** at `<execution-directory>/.hankweave-runtime.lock`, without a native dependency. All commands use a fixed 60-second stale timeout and 5-second heartbeat interval to leave headroom for synchronous work and ensure consistent takeover decisions; there is no config, environment, or CLI override. Runtime startup retries acquisition for up to 70 seconds so a supervised relaunch can reclaim an abandoned lease once it expires; cleanup and journal maintenance fail promptly on a fresh lease. Graceful shutdown releases ownership after writers drain. See [recovery behavior](README.md#recovering-an-interrupted-execution).
- Ownership is cooperative: paused live owners can lose an expired lease and terminate immediately on detecting that loss. Old PID markers are ignored. Concurrent old/new locking implementations are unsupported.

### Fixed
- **Startup errors print once** — a failed start (an invalid hank, a rejected model) printed its message, then repeated it at the top of the stack trace; the trace now holds only the stack frames.
- **Claude Code's guessed price for models it does not know** — the pinned CLI bills an unrecognized model at its default model's rate and marks the usage `costBasis: "unknown"`; such entries are now re-priced from the model catalog, and the CLI's `[claude-code:unrecognized_model]` signal is logged.
- **One malformed model row no longer empties the registry** — model data is validated row by row, in the bundled snapshot, the cache, and the `fetch-models-dev` script.
- **`pi/<provider>/<model>` takes capabilities and price from that exact model** — it used to borrow them from a fuzzy neighbour (`pi/amazon-bedrock/us.anthropic.claude-haiku-4-5-…` was budgeted as an EU Opus 4.5).
- **A hank's `overrides` survive a bad codon model during settings resolution** — settings now parse only the `overrides` block, so an unknown codon model can no longer silently drop the hank's budget and model overrides; remote and bundle summaries likewise no longer validate models before the catalog loads.
- **An invalid `hankweave.json` stops startup with its error** — it was silently ignored, dropping every setting in it, budget ceilings included. Now that model names resolve exactly, a `model` in it that the catalog does not know would otherwise have discarded the whole file.
- **`hankweave pack` accepts the models a run accepts** — it validated models against the bundled snapshot only, so a hank whose model came from its own `models` block or the model cache validated and ran but failed to pack. Pack now checks names against the catalog a run starts from (bundled data, cache, probe results, the hank's own `models` block) and Pi's offline catalog, with no credentials and no network — authors pack without runtime keys — and reports a `models` entry the catalog cannot use as a `models-block` warning.
- `--diet-journal` and `--restore-journal` now fail with `Execution directory not found` on a missing path instead of creating an empty directory tree while acquiring the lease.
- Execution leases now live inside the execution root, so writable executions under read-only parents and containers sharing an execution volume use the same lock. Cleanup preserves the lease until artifact removal finishes and reports when the outer directory must remain. Fresh starts preserve the lease; replay excludes source leases and never cleans an execution after losing ownership.
- Workspace file listing and checkpoint deltas now let every `git ls-files` they spawn finish before reporting a failure. A plain `Promise.all` rejected on the first failing process while its siblings were still running with the work tree as their cwd, so anything that removed the work tree on that failure raced them; on Windows that surfaced as `EBUSY` when deleting the directory (the flaky `file queries fail closed and refuse before initialization` unit test on `windows-latest`)
- Shutdown captures independent trace inputs before journal compression, releases ownership, then uploads asynchronously. Trace configuration checks no longer block lease renewal. Upload output goes to the console after release, and temporary snapshots are cleaned up on completion or failure.
- Startup, journal finalization, and cleanup retain the same lease throughout their protected work. The library reports lease loss through an internal fatal handler that bypasses write-producing shutdown.
- A rejected startup or run renewal cannot queue `RunStarted` without ownership. Interrupted runs are recovered from persisted state, independently of the lock and attachment metadata.
- Cleanup claims ownership for the entire deletion instead of relying on an advisory liveness check. Active leases block deletion; expired leases can be reclaimed.
- In-process run renewal preserves the actual bound server and proxy ports.
